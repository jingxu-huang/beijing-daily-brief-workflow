# 测试版 · 融资条目企业速览规范

> 适用范围：仅 `business_v2_strict`、`business_v2_balanced`、`business_v2_recall`。正式 `legacy` 日报不使用本规范。

## 输出模板

融资条目仍保持两段，不新增列表、表格或“解读”段。第二段替换为以下紧凑写法：

```markdown
**被投方速览：** {公司}主营{产品/服务}，面向{客户/使用者}，主要通过{订阅/按量计费/抽佣/广告/项目服务等已证实方式}变现；最近公开估值为{金额及披露时间}。如无可靠披露，写“公开估值暂未披露”。（{主信息来源}）
```

不另写行业意义、投资逻辑、发展展望或未被原始资料支持的“亮点”。主营与商业模式可以合并为一个分句；估值为第二个分句即可。

## 研究与审计合同

1. 自动化候选审核默认只能读取冻结新闻原文，不能联网检索。此模式只可使用原文可证实的主营、商业模式和估值；缺失字段必须写“原文未说明”或“公开估值暂未披露”。若后续增加独立、可审计的检索步骤，才可核查官网、融资方/投资方公告和可信媒体报道，官网或融资公告优先。
2. 只写各字段有明确出处的事实。没有可靠商业模式资料时写“公开资料未明确披露其主要变现方式”；没有可靠估值资料时写“公开估值暂未披露”。不得根据行业惯例、融资金额或模型推断补写。
3. 每个日期在 Git 外的运行数据目录保存 `日报状态/测试版-融资企业资料-YYYYMMDD.json`。每家公司一条记录，至少包含：
   - `company`、`report_item_url`、`researched_at`；
   - `business`（`value`、`source_url`、`publisher`）；
   - `business_model`（`value`、`source_url`、`publisher`，或 `status: not_disclosed`）；
   - `valuation`（`value`、`as_of`、`source_url`、`publisher`，或 `status: not_disclosed`）；
   - `sources_checked`（已核查链接列表）和 `audit_scope`（`source_only` 或 `web_verified`）。
4. 日报正文只保留紧凑速览和原融资新闻链接；补充检索链接保存在上述审计文件，不在正文堆叠，以免破坏阅读体验。
5. 同一公司当日多条融资/资本新闻合并时，共用一条资料记录，并在记录中列出所有 `report_item_url`。

## 不通过条件

- 公司主体无法与融资新闻中的被投方对应；
- 将融资额、历史轮估值或媒体传闻写成当前估值；
- 没有审计来源却写入公司业务、商业模式或估值事实；
- 只用搜索摘要、转载标题或模型记忆作为资料依据。
