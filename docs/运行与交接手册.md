# 资讯日报运行与交接手册（2026-09-28）

本手册面向获授权的维护者，随当前**公开 Skill 仓库**发布。固定飞书索引地址、群 ID、账号授权和历史登记不在公开仓库内，须由拥有者通过私有渠道移交。业务细则以 [`../资讯日报-skill/SKILL.md`](../资讯日报-skill/SKILL.md)、[`editorial_policy.yaml`](../资讯日报-skill/editorial_policy.yaml)、[`sources.yaml`](../资讯日报-skill/sources.yaml) 为准，本文只说明实际生产链路、权限、安装和验收。

## 一句话调用与代码归属

交给 Codex 的一句话：**“按 `jjjjasonng-commits/beijing-daily-brief-workflow` 当前代码中的 `资讯日报-skill/SKILL.md` 和 `docs/运行与交接手册.md`，先审计私有授权与历史登记，再在我批准后恢复并验收正式日报与测试三版；保留正式/测试隔离，复用当天冻结源快照，质检及飞书权限通过后只更新各自既有索引，不发群消息，失败时报告真实断点。”**

已配置机器安装两条每日调度的一条命令（在本工作流目录执行）：

```bash
bash automation/install_parallel.command
```

这个命令只安装/更新正式守门器与测试矩阵的 `launchd` 任务，不立即手动发布日报；它要求私有配置、两个**既有**索引登记和飞书无群消息模式已就绪。新机器先按下文迁移配置、授权和登记，再执行。源码以本独立仓库为交接目标；Codex skill 应指向本仓库的 `资讯日报-skill/`。原始仓库为 `evalee101010/beijing-daily-brief-workflow`，Mico 私有仓库保存过并行开发快照；两者的历史不能直接覆盖当前代码。参见 [`UPSTREAM.md`](../UPSTREAM.md)。

## 每天实际发生什么

固定时间窗为**北京时间昨日 15:00（含）到今日 15:00（不含）**，由可信 UTC 换算。只允许在窗口闭合后发布；历史日期重跑必须说明滚动 RSS 可能已丢失旧条目，不能拿后来抓到的内容冒充当时 15:00 快照。

```text
公开源（sources.yaml） ── 取列表/全文/发布时间 ── 时间窗、去重、旧闻检查 ─┬─ 正式：legacy → 草稿 → Codex 正文 → 质检/修复 → 图片 → 飞书正式文档 → 正式索引
测试可用公众号源 ── 低频评估/同步 ── 15:00 共同原始快照 ─────────────┴─ 测试：共享 Codex 候选审核（可降级）
                                                                    ├─ 严格 → 独立正文/QA/飞书文档 ┐
                                                                    ├─ 平衡 → 独立正文/QA/飞书文档 ├─ 一次更新测试索引
                                                                    └─ 高召回 → 独立正文/QA/飞书文档 ┘
```

| 环节 | 正式版 | 测试版 |
|---|---|---|
| 启动 | `launchd` 正式守门器每 30 秒检查状态，14:30 可预抓，15:00 关窗后由 `run_daily_with_feishu.sh` 生成；失败按守门器状态机重试 | 独立 `launchd` 于本机北京时间 15:00 调 `run_daily_test_matrix.sh`；不得抢占正式版，进程优先级较低 |
| 源与筛选 | `sources.yaml` 在役公开源；`legacy` 策略；不读测试共享快照 | 同一窗口只抓一次原始候选；每个 profile 从此快照离线回放；公众号通道仅在当次 `healthy/cached` 时启用，失败则标明降级为纯公开源，不得假报覆盖 |
| 公众号旧系统 | WeWe RSS 强制排除；WeRSS 当前未启用、旧探测代码仅留档；wechat-download-api 不接入日报 | WeWe/WeRSS 显式排除；`weread-omni` 仅作条件性测试源，**不是已证明稳定的生产来源**；账号覆盖用实际 `x/27`，不是默认写满 27 |
| 取舍 | 正文不少于 10 条、至少 3 个最终来源；不相关内容不能补数 | 严格版不少于 10 条且无明确不相关；平衡/高召回目标各 25 条，但质量池耗尽可低于目标，硬下限仍为 10 条、3 来源；三版不可互相冒充 |
| Codex | `run_daily.sh` 负责成稿、最多两轮质检修复；正式版不调用测试候选审核 | `codex_candidate_audit.py` 对共同快照做一次有时限审核；失败/超时记录 fallback，不阻断原生筛选。三篇正文各自成稿/QA；融资速览资料只供测试版，逐事实留来源 |
| 交付边界 | 本地正式草稿、成稿、QA、manifest 独立；QA `FAIL` 不发布 | 三个独立目录及飞书文档，协调器最后只更新一次测试索引；单版失败记录状态，不得被其他版本“成功”覆盖 |

筛选顺序：源列表与真实发布时间 → 目标窗口 → 原文/正文抽取及短摘要限量补取 → URL/标题/跨日报旧闻去重 → 业务标签与正反证据判为 `accept/review/reject` → 精选及安全备选 → 测试共享审核与补位 → 正文 → `check_report.py` 逐条查时间、事实、长度、Source 表、精选交付及图片相关性。`editorial_policy.yaml` 控制三版差异；`sources.yaml` 是来源清单、每赛道上限和 QA 阈值的唯一配置，不得偷偷在成稿阶段丢掉精选。公众号文章必须有可信发布时间和足够正文；无正文不得用模型记忆填充。小规模 AI 训练/跑分/测试默认低价值，多源豁免必须是不同发布者报道**同一具名模型、版本和动作**；普通产品、头部模型真正发布及目标融资不能被这个专项门禁误杀。融资企业主营、商业模式、估值的测试版补充见 [`测试版融资补充规范.md`](../资讯日报-skill/format/测试版融资补充规范.md)，查不到就注明未披露，不能猜。

## 飞书固定目标、权限与通知

| 目标 | 已确认的固定地址 | 战略小组权限 | 消息 |
|---|---|---|---|
| 正式日报索引《资讯日报链接索引》 | 由拥有者私下提供并核验原地址 | `full_access`（可管理） | 不发群消息 |
| 测试日报索引《资讯日报测试版本索引》 | 由拥有者私下提供并核验原地址 | `edit`（可编辑） | 不发群消息 |
| 每日正式文档 | 当天链接由正式索引记录，同日原位更新 | `full_access` | 不发群消息 |
| 三篇每日测试文档 | 当天链接由测试索引的严格、平衡、高召回三列记录，同日同版本原位更新 | `edit` | 不发群消息 |

测试索引每日期**只有一行**，三版各一列，其余列共用：公开源、公众号源、质检、生成时间。公开源和公众号源都记录“抓到／精选／候补／最终采用”；公众号源另记“启用否、实际覆盖 x/27”。QA `FAIL` 或授权失败不得显示为已交付。原索引链接需先用本人授权的飞书账号打开核对；仅有链接不等于有写入/授权能力。当前模式 `RIBAO_ENABLE_FEISHU=1`、`FEISHU_DOC_ONLY=1`、`FEISHU_DAILY_INDEX=1`、`RIBAO_GROUP_MESSAGES=0`，正式文档和索引 `full_access`，测试文档和索引 `edit`。即使手动运行失败也不应发群消息；本机系统通知可以保留。不得用 `--mode new` 建一个同名新索引来“修复”找不到注册表。

## 私有配置、迁移与重新启动

1. 克隆 `jjjjasonng-commits/beijing-daily-brief-workflow` 并核对当前提交。运行 `bash bootstrap_new_mac.command` 可装基础依赖、公开源适配器、skill 符号链接及正式守门器；它会忽略旧 `RIBAO_ENABLE_WEWE=1`，不得安装历史扫码服务。对新机器，先编辑 Git 忽略的 `config.env`，再启用飞书；基础安装脚本不能替代下面的索引续接。
2. 在**已有的、非系统根盘运行数据目录**配置 `RIBAO_DATA_ROOT`、`RIBAO_PYTHON_BIN`、`RIBAO_ENABLE_FEISHU=1`、`FEISHU_DOC_ONLY=1`、`FEISHU_DAILY_INDEX=1`、`RIBAO_GROUP_MESSAGES=0`、战略小组的 `FEISHU_REPORT_CHAT_ID`（测试可用 `FEISHU_TEST_INDEX_CHAT_ID` 指向同一组）。设置飞书 `user` 导入/授权身份；先完成 Codex CLI 与 lark-cli 授权。密钥、群 ID、Cookie、会话状态和本地日报数据均不入库。测试索引权限固定 `edit`，不要把配置中的正式 `full_access` 直接套到它。
3. 最稳妥是从旧机器私密迁移 `$RIBAO_DATA_ROOT/日报状态/feishu-daily-index.json`、`feishu-docs.json` 与 `$RIBAO_DATA_ROOT/测试版/日报状态/feishu-test-index.json`、`feishu-docs.json`、`feishu-test-runs.json`；测试版三个运行目录及共享快照也应私密迁移以保留去重/复盘。同日文档 registry 不在时，自动重跑可能新建重复日报，先恢复再运行。
4. 若**仅丢失索引登记**而飞书原文档仍在，先从拥有者的私有交接材料取回两个原索引链接并核对，使用环境变量提供目标，只登记目标、不改文档内容：

   ```bash
   set -a; source config.env; set +a
   python3 local-only/feishu-bot/update_daily_index.py --register-target "$RIBAO_EXISTING_FORMAL_INDEX_URL"
   RIBAO_TEST_MODE=1 RIBAO_DATA_ROOT="${RIBAO_TEST_DATA_ROOT:-$RIBAO_DATA_ROOT/测试版}" python3 local-only/feishu-bot/update_test_index.py --register-target "$RIBAO_EXISTING_TEST_INDEX_URL"
   ```

   命令只登记既有索引，不重建历史日报链接；若原日日报 registry 已丢失，必须先从私有备份/飞书索引核对并恢复，再启用自动生产。若登记目标与已有文件不同，命令默认拒绝，须人工确认差异，禁止自动替换。
5. 先 `bash scripts/verify.sh`，再运行只读的 `bash automation/install_parallel.command --check`。它会逐项提示缺少的私有配置、Codex 登录、飞书 **user** 授权、战略小组 ID、两份索引登记及历史日报链接登记，不输出凭据，也不安装任务；只有全部通过才运行 `bash automation/install_parallel.command`。两个标签分别为 `com.example.beijing-daily-brief-guard` 与 `com.example.beijing-daily-brief-test-matrix`；查看 `launchctl print "gui/$(id -u)/标签"`。测试版 `StartCalendarInterval=15:00` 使用**本机时区**，新机器必须将 macOS 时区设为上海/北京，否则虽有闭窗保护，也可能错过当天正常启动。休眠可造成延迟或错过唤醒，安装后要看实际次日 manifest，不以“标签存在”代替验收。
6. 新机器首次不要在开放窗口内手动生成。窗口闭合后可分别手动运行 `RIBAO_TARGET_YMD=YYYYMMDD bash run_daily_with_feishu.sh` 和 `RIBAO_TARGET_YMD=YYYYMMDD bash run_daily_test_matrix.sh`；测试三版共用一次快照。正式版优先；手动重跑前确认该日期无另一实例正在运行，并核对目标日期，防止并发覆盖同日文档。

截至本手册编写时的本机只读检查：正式守门器已安装，测试矩阵 `launchd` 标签尚未安装。`automation/install_parallel.command` 是完成此缺口的显式操作；仅提交代码不会自动改变机器上的调度状态。

## 本地状态、验收与失败处理

正式产物在 `$RIBAO_DATA_ROOT/{日报草稿,日报文档,日报质检,日报状态}/`；每日状态在 `日报状态/run-manifest-YYYYMMDD.json`，正式飞书登记在 `feishu-docs.json`、`feishu-daily-index.json`。测试产物在 `${RIBAO_TEST_DATA_ROOT:-$RIBAO_DATA_ROOT/测试版}/`：`共享快照/YYYYMMDD/原始候选.json`（同日重跑复用，不重新联网混源），`运行/YYYYMMDD/{strict,balanced,recall}/` 各自有草稿、成稿、QA、manifest、飞书登记；共同测试索引登记为 `日报状态/feishu-test-index.json`。选择审计、融资资料和版本归档也仅在 Git 外运行目录。公开源 RSS 是滚动窗口，不保证事后能重建几天前的完整快照；若无原始快照，必须注明“历史源不完整”，不能拿正式版或相邻日期的素材代替。

每次验收至少核对：目标日期/时间窗；公开源抓取数、失败数、不同来源数；公众号启用状态、实际覆盖及全文率；三版共同快照哈希/路径；初筛 `accept/review/reject` 与精选、候补、最终采用数；Codex 审核是否 `applied/fallback`；每篇正文不少于对应硬下限、Source 表与正文来源一致、融资速览可回溯、图片失败不吞正文；`check_report.py` 结论；飞书文档回读及权限；两份索引当天行/链接；`messages_sent=false`。正式守门器 `generated` 或群投递模式的 `sent` 才算成功，测试矩阵状态需三版逐个看，`partial_failure` 不能汇报“全部完成”。

失败时按“源 → 快照 → 筛选 → Codex 审核 → 正文/修复 → QA → 图片 → 飞书文档 → 授权 → 索引”定位，不要通过调低门禁或混入旧窗口素材硬凑数量。公开源不够与筛选误杀必须分别检查：先看窗口内**原始快照**是否完整，再比对被 `review/reject` 的逐条理由；成稿少还要检查精选 URL 是否被写作阶段遗漏以及安全备选是否补齐。测试版可以失败并留记录，不能污染正式版。用户已明确“先修测试版、正式版未经批准不改”；正式版修改需单独确认。旧 WeWe/WeRSS/下载 API 的失败和风控记录保留供追溯，不能因源码仍在便重新启用。

提交前运行测试与源码审计；本公开仓库不允许固定索引链接、群 ID 或运行数据。不要提交 `config.env`、`auth.json`、飞书 ID/Token、二维码、日志、缓存、真实日报和状态文件。未来修改先在明确的工作分支验证，再按仓库维护流程合并；不要覆盖历史提交。
